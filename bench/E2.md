## Manual check (Oct 30, 2026)

| Arrangement | Average time | Average cost | The main session's Opus cost |
|---|---:|---:|---:|
| Parallel (3 Sonnet reviewers at the same time) | ~174 s | US$ 0.69 | ~US$ 0.53 |
| Sequential (Opus alone, one module at a time) | ~127 s | US$ 0.51 | ~US$ 0.51 |

**In a small project, parallel lost on both measures:** +37% time and +37% cost. The Opus cost barely changed: the reviewers did not take work off it, they only added to it. Opening a subagent, waiting for all of them and consolidating has a fixed cost; with 3 short files, that cost is bigger than the gain.

**Quality (run 1 answers read in full):**
- **Parallel:** covered more (21 findings after merging repeats) and separated 6 "OWNER DECISION" items. The coordinator warned: "I also did not read the source code myself: the table joins what the reviewers found". **One finding was false:** "the coupon lookup accepts names like `'constructor'` or `'toString'`... the total comes out NaN" (medium severity). Checked by running it: all four names give "Coupon not found", because the code uppercases the coupon before looking it up.
- **Sequential:** brought the most valuable business finding with the math done: "Using the coupon can make the order more expensive... R$ 151.00 without the coupon and R$ 155.90 with FIRST20" (checked: 15100 without shipping; 13100 + 2490 of North shipping = 15590). It left a proof test for each finding.
- **Both run 1s could not run `node`:** the folder had never been opened in interactive mode, so the project's `allow` permissions were ignored (bench B3). Both warned that the proof was pending, and neither worked around it.

**Honest reading:**
1. Parallel is not free. It pays off when each front is big enough to pay for opening the subagent and when whoever consolidates checks what they receive.
2. The E1 rule showed up again: whoever consolidates without reading the code passes on the wrong finding with the same confidence as the right ones.
3. To put a team to work on its own, open the folder once in interactive mode; without that, nobody runs tests.
4. Small sample (2 runs per arrangement, 1 project of 3 files): it is a measured case, not statistics.
